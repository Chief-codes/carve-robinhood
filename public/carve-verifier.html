What this proves—and what it does not

The verifier reads contentRegistry, imageRoot, audioRoot and websiteRoot from the token, then checks the manifest commitment and every stored chunk. It reports a fixed canonical block and exports decoded and encoded hashes.

Current Carve tokens do not expose a tokenURI getter. This is a local decoder interface, not an onchain metadata getter. Data URIs are constructed here from verified bytes; they are not fetched from a separate server.

Hash integrity does not certify a token’s authenticity, safety, ownership, or value. HTML can contain active scripts. The optional preview uses an opaque sandbox and restrictive content policy; downloaded HTML and manually pasted raw data URIs do not carry this viewer’s isolation.

No keys. No wallet. No analytics. No remote application scripts. Selected absent slots are reported, not fabricated. One verified file is limited to 1 MB by the current decoder.
